# 토플 리스닝 학습용 오디오 플레이어 기획서 v2

## 1. 프로젝트 개요

Language Reactor(https://www.languagereactor.com/video-file)의 미디어 파일 플레이어를 레퍼런스로 한 클론 + 개선 프로젝트.
토플 리스닝 mp3 파일을 올려서 OpenAI Whisper STT 기반으로 문장별 자막을 생성하고, 영어 원문 + 한국어 번역을 나란히 보면서 학습하는 웹앱.

### 왜 만드는가

- Language Reactor가 영어 학습용 오디오 플레이어로는 현존 최고 수준이지만 치명적 불편함이 있음
- 파일을 매번 1개씩만 올릴 수 있고, 웹에 아무 히스토리도 안 남음 → 매일 학습할 때 어제 뭘 했는지 기억해야 함
- 키보드 방향키가 5초 단위 이동만 됨 → 문장별로 잘 끊어놨는데도 문장 단위 이동이 안 됨
- 재생목록 없음 → 여러 mp3를 묶어서 관리하는 기능 없음

## 2. 기술 스택

### 서버

| 구성 | 선택 | 이유 |
|------|------|------|
| 런타임 | **Node.js** | 가장 넓은 생태계, 검증된 안정성. 별도 설명 불필요. |
| 웹 프레임워크 | **NestJS** | Angular 스타일의 모듈/컨트롤러/서비스 아키텍처. DI(의존성 주입) 내장, 데코레이터 기반 라우팅, TypeScript 퍼스트. 엔터프라이즈 검증 완료. 내부적으로 Express 또는 Fastify 어댑터 선택 가능 (기본 Express). |
| 데이터 저장 | **파일시스템 (JSON)** | mp3 파일은 로컬 파일시스템에 직접 저장. 메타데이터(STT 결과, 재생 위치, 재생목록)는 JSON 파일로 관리. DB 불필요. |

### 외부 API

| 용도 | 선택 | 비용 |
|------|------|------|
| STT | **OpenAI Whisper API** | $0.006/분. 토플 파일 100개(약 500분) 처리해도 ~$3. segment-level 타임스탬프 정확도가 가장 높음. |
| 번역 | **OpenAI GPT API** (또는 Google Translation API) | STT 텍스트를 한국어로 번역. 문장 수십 개 수준이라 비용 미미. |

### 프론트엔드

| 구성 | 선택 |
|------|------|
| 기본 | HTML + CSS + TypeScript |
| 오디오 | HTML5 `<audio>` 태그 |
| UI | 다크 모드 기본 |

### 왜 Whisper인가 (Gemini 대비)

OpenAI Whisper API를 선택한 핵심 이유는 **타임스탬프 정확도**. 이 앱에서 ←/→ 키로 문장 단위 점프를 하려면 각 문장의 시작/끝 시간이 정확해야 함.

- **Whisper**: 전용 STT 모델. `timestamp_granularities[]` 파라미터로 segment-level, word-level 타임스탬프를 명시적으로 요청 가능. 정확도 최상.
- **Gemini**: 멀티모달 LLM이 오디오를 "이해"하는 방식. 타임스탬프는 프롬프트로 요청하지만, 실제 테스트에서 3시간 30분 회의 녹음의 타임스탬프가 실제와 크게 불일치하는 사례 보고됨 (1:04:00 표시 → 실제 3:31:05).
- **비용**: Whisper $0.006/분, Gemini Flash 무료 티어 있지만 타임스탬프 부정확으로 이 용도에는 부적합.

## 3. 핵심 기술 구현 원리

### 3-1. STT → 문장 분리 → 타임스탬프 기반 재생 제어

이 앱의 핵심 메커니즘. 원리는 단순함.

**Step 1: Whisper API 호출 → 타임스탬프 배열 획득**

서버에서 mp3 파일을 Whisper API에 전송하면 아래와 같은 segment 배열이 반환됨:

```json
{
  "segments": [
    { "id": 0, "start": 0.0,  "end": 3.24, "text": "The professor discussed the impact of..." },
    { "id": 1, "start": 3.52, "end": 7.11, "text": "This theory suggests that early..." },
    { "id": 2, "start": 7.40, "end": 11.8, "text": "However, recent studies have shown..." }
  ]
}
```

각 segment에 `start` (초), `end` (초), `text` (텍스트)가 포함됨. 이 배열이 모든 기능의 기반.

**Step 2: 프론트엔드에서 `audio.currentTime`으로 재생 제어**

HTML5 `<audio>` 태그는 `currentTime` 속성으로 현재 재생 위치를 초 단위로 읽기/쓰기 가능:

```js
const audio = document.querySelector('audio');

// 특정 문장으로 점프 — 이게 전부
audio.currentTime = segments[targetIndex].start;

// 현재 어떤 문장이 재생 중인지 찾기
const currentIdx = segments.findIndex(
  s => audio.currentTime >= s.start && audio.currentTime < s.end
);
```

**Step 3: 키보드/클릭 이벤트와 연결**

```
← 키 누름 → 현재 segment의 start로 이동 (이미 start 근처면 이전 segment로)
→ 키 누름 → 다음 segment의 start로 이동
문장 클릭 → 해당 segment의 start로 이동
```

음악 앱에서 가사 특정 줄을 누르면 거기로 점프하는 것과 완전히 동일한 원리. 음성 파일 자체에 특별한 구조가 있는 게 아니라, **별도의 타임스탬프 데이터**를 만들어서 `currentTime`을 세팅하는 것.

**Step 4: 자동 일시정지 (AP)**

`timeupdate` 이벤트에서 현재 시간이 segment 끝을 넘으면 `audio.pause()`:

```js
audio.addEventListener('timeupdate', () => {
  if (autoPauseEnabled && audio.currentTime >= segments[currentIdx].end) {
    audio.pause();
  }
});
```

### 3-2. 파일 저장 — 로컬 파일시스템 직접 관리

**mp3 파일은 서버의 파일시스템에 직접 저장.** 브라우저 저장소(IndexedDB)를 사용하지 않음.

```
~/toefl-player/
├── src/
│   ├── main.ts                  ← NestJS 엔트리포인트
│   ├── app.module.ts            ← 루트 모듈
│   ├── files/                   ← 파일 관리 모듈
│   │   ├── files.module.ts
│   │   ├── files.controller.ts  ← 업로드, 목록, 삭제, 오디오 스트리밍 API
│   │   └── files.service.ts     ← 파일시스템 읽기/쓰기, Whisper API 호출
│   ├── playlists/               ← 재생목록 모듈
│   │   ├── playlists.module.ts
│   │   ├── playlists.controller.ts
│   │   └── playlists.service.ts
│   └── stt/                     ← STT + 번역 모듈
│       ├── stt.module.ts
│       └── stt.service.ts       ← Whisper API, 번역 API 호출
├── public/                      ← 프론트엔드 (HTML/CSS/JS) — ServeStaticModule로 서빙
├── data/
│   ├── meta.json                ← 파일 메타데이터 + 재생 위치 + 재생목록
│   ├── audio/                   ← mp3 파일 저장소
│   │   ├── practice_09.mp3
│   │   ├── practice_10.mp3
│   │   └── lecture_01.mp3
│   └── stt/                     ← STT 결과 캐시 (파일별 JSON)
│       ├── practice_09.json
│       ├── practice_10.json
│       └── lecture_01.json
├── package.json
├── tsconfig.json
└── nest-cli.json
```

**파일 등록 흐름:**
1. 브라우저에서 mp3 파일을 드래그 앤 드롭 (여러 개 한번에 가능)
2. 프론트 → 서버 API로 multipart 업로드
3. 서버가 `data/audio/`에 파일 저장
4. 서버가 Whisper API 호출 → STT 결과를 `data/stt/{파일명}.json`에 저장
5. 메타데이터(파일명, 길이, STT 상태, 재생 위치) `data/meta.json`에 기록

**왜 파일시스템인가:**
- 브라우저 캐시 삭제해도 데이터 안 날아감
- 용량 제한 없음 (IndexedDB는 도메인당 수백 MB 제한)
- 기기 이동 시 `data/` 폴더 통째로 복사하면 끝
- mp3 파일을 탐색기에서 직접 확인/관리 가능
- 서버 API가 파일 목록을 제공하므로 브라우저에서 매번 올릴 필요 없음

### 3-3. 브라우저와 서버의 역할 분담

```
┌─────────────────────────────────────────────────────────┐
│  브라우저 (프론트엔드)                                     │
│  - <audio> 태그로 mp3 재생/정지/시간 이동                   │
│  - segments 배열 기반 UI 렌더링 (자막, 세그먼트 바)          │
│  - 키보드 이벤트 → currentTime 세팅                        │
│  - 재생 위치 변경 시 서버에 진도 저장 요청                    │
├─────────────────────────────────────────────────────────┤
│  서버 (Node.js + NestJS)                                 │
│  - 정적 파일 서빙 (프론트엔드 + mp3 파일)                    │
│  - 파일 업로드 수신 → data/audio/에 저장                    │
│  - 새 파일 → OpenAI Whisper API 호출 → STT 결과 저장       │
│  - STT 텍스트 → 번역 API 호출 → 번역 결과 저장             │
│  - 파일 목록, 재생 위치, 재생목록 CRUD API                  │
└─────────────────────────────────────────────────────────┘
```

## 4. 서버 API 설계

### 파일 관리

| Method | Path | 설명 |
|--------|------|------|
| `GET` | `/api/files` | 전체 파일 목록 (메타데이터 포함) |
| `POST` | `/api/files/upload` | mp3 파일 업로드 (multipart, 다중 파일) |
| `DELETE` | `/api/files/:id` | 파일 삭제 (mp3 + STT + 메타데이터) |
| `GET` | `/api/files/:id/audio` | mp3 파일 스트리밍 (Range 요청 지원) |
| `GET` | `/api/files/:id/stt` | STT 결과 (segments 배열) 조회 |
| `POST` | `/api/files/:id/stt` | STT 재처리 트리거 |

### 진도 관리

| Method | Path | 설명 |
|--------|------|------|
| `PUT` | `/api/files/:id/progress` | 재생 위치 저장 (currentTime, 완료 여부) |
| `GET` | `/api/files/:id/progress` | 재생 위치 조회 |

### 재생목록

| Method | Path | 설명 |

| `PUT` | `/api/playlists/:id` | 재생목록 수정 (이름, 순서, 파일 추가/제거) |

## 5. 레퍼런스 분석 — Language Reactor 미디어 파일 플레이어

### 5-1. 재생 화면 (핵심 학습 화면)

**상단 컨트롤 바**
- 좌측: "돌아가기" 버튼 (라이브러리로 복귀)
- 우측: 키보드 단축키 안내, 설정, 재생 속도(0.5x~2x)

**오디오 플레이어 바**
- 재생/일시정지 버튼 (▶/⏸)
- 시크바: 프로그레스 바, 드래그로 위치 이동 가능
- 남은 시간 표시 (예: -00:32)
- 볼륨 버튼 + 볼륨 슬라이더
- 자동 일시 중지(AP) 토글 버튼

**세그먼트 타임라인 바 (시크바 바로 아래)**
- 전체 오디오를 문장별 구간으로 나눈 블록들이 가로로 배열
- 각 블록의 너비는 해당 문장의 길이에 비례
- 블록 사이에 갭이 있어서 문장 경계가 시각적으로 구분
- 현재 재생 중인 문장의 블록에 커서 표시
- 블록 클릭 시 해당 문장으로 즉시 점프

**2컬럼 자막 패널 (메인 영역)**
- 좌측 컬럼: 영어 원문 (STT 결과)
- 우측 컬럼: 한국어 번역
- 각 행이 하나의 문장 단위
- 현재 재생 중인 문장: 재생 아이콘(▶) 표시 + 행 하이라이트
- 아직 재생 안 된 문장: 텍스트가 흐리게(반투명) 표시
- 이미 지나간 문장: 정상 밝기
- 문장 클릭 시 해당 문장 시작 지점으로 오디오 점프
- 자동 스크롤: 재생 진행에 따라 현재 문장이 보이도록 자동 스크롤

### 5-2. 현재 한계점 (이 프로젝트가 해결하는 문제)

1. **파일 관리 불가**: 파일을 매번 1개씩만 올릴 수 있고, 브라우저에 아무것도 저장 안 됨.
2. **문장 단위 키보드 이동 불가**: 키보드 좌우 방향키가 5초 단위로만 이동됨.
3. **재생목록 없음**: 여러 mp3를 묶어서 관리하는 기능 없음.

## 6. 개선 기능 설계

### 6-1. 파일 라이브러리 + 재생목록 시스템

**다중 파일 업로드 + 라이브러리**
- 초기 화면에서 mp3 파일을 여러 개 한번에 드래그 앤 드롭으로 등록
- 서버가 `data/audio/`에 저장 → 브라우저 재방문 시에도 파일 목록 유지
- 라이브러리 화면: 파일 목록을 리스트로 표시 (파일명, 길이, 추가일, 진행률)

**재생목록 (Playlist)**
- 유튜브 재생목록처럼 폴더/그룹 생성 가능 (예: "TOEFL Practice Set 1", "Week 3")
- 드래그로 순서 변경, 파일 추가/제거
- 재생 화면에서 좌측 사이드바에 미니 플레이리스트 표시 (접기 가능)

**UX 흐름**
사이트 접속 (localhost:3000) → 라이브러리 화면 (최근 학습 파일이 상단에 하이라이트, "이어서 듣기" 버튼) → 파일 클릭 → 마지막 위치부터 이어 재생 / 또는 새 파일 여러 개 드래그해서 한번에 추가 → 서버가 자동으로 STT 처리

**업로드 후 처리 흐름**
1. 브라우저에서 파일 드래그 앤 드롭
2. 서버 API로 multipart 업로드 → `data/audio/`에 저장
3. 서버가 백그라운드에서 Whisper API 호출 (프론트에 "처리 중" 표시)
4. STT 완료 → 번역 API 호출
5. 결과를 `data/stt/{파일명}.json`에 저장
6. 프론트에 완료 알림 → 바로 재생 가능

### 6-2. 문장 단위 키보드 네비게이션

**키보드 단축키**

| 키 | 동작 |
|---|---|
| `←` | 이전 문장 시작 지점으로 점프 |
| `→` | 다음 문장 시작 지점으로 점프 |
| `Shift + ←` | 5초 뒤로 (세밀 조정용) |
| `Shift + →` | 5초 앞으로 (세밀 조정용) |
| `Space` | 재생/일시정지 |
| `R` | 현재 문장 처음부터 다시 듣기 |
| `Shift + R` | 현재 문장 무한 반복 토글 |
| `Enter` | 번역 숨기기/보이기 토글 |
| `↑` / `↓` | 재생 속도 0.1 단위 조절 |

**구현 원리**
- STT 결과의 segments 배열에서 현재 `audio.currentTime`이 속한 segment를 탐색
- ← 누르면 현재 segment의 start로, 이미 start 근처(1초 이내)면 이전 segment start로 이동
- → 누르면 다음 segment의 start로 `audio.currentTime` 세팅

### 6-3. 재생 화면 UX 개선

**현재 문장 하이라이트 강화**
- 현재 재생 중인 문장을 화면 중앙에 고정
- 위아래 맥락 문장은 점진적으로 투명도 낮춤

**학습 모드 토글** (상단 또는 설정에서 전환)
- 기본 모드: 영어 + 한국어 둘 다 표시, 자동 재생
- 리스닝 모드: 한국어 번역 숨김, 문장 클릭하면 번역 일시 표시 → 자기 테스트
- 딕테이션 모드: 영어 텍스트도 숨김, 듣고 타이핑 → 정답 비교
- 쉐도잉 모드: 한 문장씩 자동 일시 정지 + 마이크 녹음 → 본인 발음과 원본 비교 재생

**미니 플레이리스트 사이드바**
- 재생 화면 좌측에 현재 재생목록의 파일 리스트
- 현재 파일 하이라이트, 다음/이전 파일 바로 클릭
- 접을 수 있는 패널 (학습 시 넓게 쓸 때는 접기)

## 8. 유지해야 할 레퍼런스 기능

1. STT 기반 문장 분리 + 타임스탬프 매핑

4. 자동 일시 중지 (AP) — 한 문장 끝나면 자동 멈춤
5. 문장 클릭으로 해당 시점 점프
6. 재생 속도 조절 (0.5x ~ 2x)
7. 자동 스크롤 (현재 재생 문장 따라감)
8. 다크 모드 UI

## 9. 우선순위

### P0 — 앱이 성립하기 위한 필수 기능

| 기능 | 이유 |
|------|------|
| mp3 다중 업로드 + 파일시스템 저장 | 핵심 페인포인트. 파일 관리가 안 되면 매일 쓸 수 없음 |
| Whisper STT + 번역 + segments 저장 | 모든 기능의 기반 데이터 |
| 2컬럼 자막 + 세그먼트 바 | 이게 없으면 앱 자체가 성립 안 됨 |
| 문장 단위 ←/→ 키보드 네비게이션 | 학습 효율 직결. 레퍼런스의 핵심 개선 포인트 |
| 진도 저장 (마지막 재생 위치 + 완료 여부) | 매일 학습 루틴의 기본 전제 |
| 파일 라이브러리 (목록 조회, 이어서 듣기) | 레퍼런스와의 핵심 차별점 |

### P1 — 학습 효율을 높이는 기능

| 기능 | 이유 |
|------|------|
| 재생목록 (폴더/그룹 관리) | 파일 10개 넘으면 필요 |
| 현재 문장 반복 재생 (R키) | 토플 리스닝 학습의 핵심 패턴 |
| 번역 숨기기/보이기 토글 | 자기 테스트용, 리스닝 모드 |
| 자동 일시 중지 (AP) | 천천히 한 문장씩 학습할 때 필수 |
| 재생 속도 조절 | 느리게 들으며 분석하거나 빠르게 복습 |

### P2 — 심화 기능

| 기능 | 이유 |
|------|------|
| 딕테이션/쉐도잉 모드 | 심화 학습 |
| 학습 통계 대시보드 | 동기 부여 |
| 데이터 내보내기/가져오기 | data/ 폴더 복사로 대체 가능하므로 우선순위 낮음 |
